# B-23 — Give each subject repository a generated size line

Split out of [B-16](B-16-run-on-the-three-subjects.md), which measured the subjects and wrote the
numbers into this repository's research. What is left is the other half of that item: a line in each
subject's own README saying what its binary is made of.

- **The decision and its reason.** It is work in *other* repositories — `shildik` and `booblik` — each
  with its own gates and its own release line, and it should be a deliberate change there rather than
  a side effect of an iteration here. Blocked by [B-17](B-17-sborka-convention.md) because the line
  should be generated by the plugin those repositories already apply, not pasted.
- **`telek` is not one of them.** It declares no native executable at all: it is a library of router
  and transport modules whose only `linuxX64` binaries are test runners. The brief listed it as one
  of three subjects with different structure, and that premise is wrong — a library has no binary to
  attribute, and its test binary is not something anybody ships.
- Does **not** cover: a number typed into a README. A figure with no provenance stops being a
  measurement the first time anything changes underneath it, which is the failure this whole
  repository is built to avoid.

- AC: the line names the binary, the Kotlin version and the date, and is produced by `sizeReport`
  rather than by hand.
- AC: `telek` gets no such line, and its README says why if the question comes up.
- Anchors: `shildik/README.md`, `booblik/README.md`,
  `gradle-plugin/src/main/kotlin/io/github/youndie/razves/gradle/SizeReportTask.kt`
